# MVP 开发计划总览

**目标**：10 个工作日内做出可玩的中途岛指挥官原型，验证"自然语言指挥参谋"的核心玩法。

**核心体验**：舰队指挥官通过命令指挥参谋，参谋根据命令提供情报、建议并执行动作。不同参谋的决策带来千变万化的玩法体验。

**设计方案**：详见 `docs/GAME_DESIGN_V2.md`

## Phase 1：核心循环（Day 1-4）

验证核心玩法：玩家通过自然语言命令指挥参谋，参谋执行并报告结果。

### Day 1：动作计数制（AP 系统）
- 实现 AP 消耗机制
- 每回合 3 个 AP（普通）/ 5 个 AP（关键）/ 2 个 AP（紧急）
- 对话和命令消耗 AP，等待不消耗
- AP 用完必须推进时间

### Day 2：骰子系统
- 实现 d100 基础骰
- 五级结果：大成功（95+）、成功（70-94）、部分成功（40-69）、失败（10-39）、大失败（9-）
- 修正值计算：自主度、风险容忍、主动性、能力值
- 骰子结果与 NPC 行为联动

### Day 3：侦察循环
- 玩家命令侦察 → NPC 执行 → 侦察机派出
- 推进时间 → 侦察检定（骰子）
- 侦察报告到达（延迟 30-60 分钟）
- 信息失真：位置误差、数量误差

### Day 4：信息延迟 + 失真
- 侦察报告有延迟（不是即时到达）
- 报告内容有误差（位置、数量）
- 多个报告整合时可能矛盾
- 玩家需要判断哪个报告更可信

## Phase 2：丰富体验（Day 5-7）

扩展 NPC、骰子和事件系统。

### Day 5：多 NPC
- 新增舰长（Murray、Mitscher）
- 新增通信官
- 不同 NPC 有不同的自主度和职责范围
- 玩家需要和多个 NPC 协调

### Day 6：双刃骰
- 优势骰：掷 2d100 取高，但同时掷代价骰
- 代价骰结果延迟揭晓
- 多派侦察、集中攻击等行为的隐藏代价
- 玩家需要权衡眼前好处和未来风险

### Day 7：连锁事件
- 攻击成功 → 日军反击事件
- 事件链：前置事件触发后续事件
- 事件对状态的影响（舰艇损伤、飞机损失）

---

## Phase 3：完整游戏（Day 8-10）

完成游戏循环和结局。

### Day 8：战斗演算
- 攻击结果计算（骰子 + 参数）
- 损失计算（飞机、舰艇）
- 战果报告（延迟到达）

### Day 9：多结局
- 五种结局：超越历史、中途岛奇迹、惨胜、惨败、Browning 独走
- 结局条件：击沉日舰数、美军损失
- 历史脚注：每个结局附带历史对比

### Day 10：内测 + 迭代
- 自测 5 遍，记录问题
- 外测 3-5 人，收集反馈
- 决策：进入 Alpha / 调整方向 / 暂停

## 核心假设验证

验证"自然语言指挥参谋"是否成立：

- [ ] 玩家会主动和不同 NPC 对话获取信息
- [ ] 玩家会根据 NPC 建议做出决策
- [ ] 骰子结果会让玩家感到惊喜/惊吓
- [ ] 信息延迟和失真会让玩家感到焦虑
- [ ] 玩家会想重玩一次试试不同选择

---

## 关键原则

- **每天结束都要有一个能 demo 的东西**，哪怕很丑
- **不允许跨天提前做后面的事**（避免方向跑偏）
- **写在 plan 里的事，做完一项划一项**
- **测试驱动**：写代码必有 pytest
