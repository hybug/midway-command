# 珊瑚海单场景 MVP 收口计划

日期：2026-11-19\
状态：工作稿；用于拆分下一轮任务，尚未修改运行规则。\
关联：`gameplay-system-roadmap.md`、`s5-command-execution-system-plan.md`。

## 交付目标

让未参与开发的玩家独立完成一局，理解至少一个决定如何影响结果，并可以重新开始。
首轮以珊瑚海为工作假设，目标实际游玩时长 20–30 分钟；时长通过试玩验证。

完整路径：

任务简报 → 可疑接触报告 → 询问参谋 → 侦察/等待/准备攻击 →
签发命令 → 推进时间 → 新证据与行动回报 → 再决策 → 结束 → 复盘 → 重开。

这是受史实启发的有限场景；简化规则和非史实分支需要明确标注。
至少包含一次初始决策和一次新证据后的调整机会。

## 范围

- 一个场景；主要决策角色为情报、航空、作战参谋，辅助岗位沿用必要编制。
- 正式命令收口到航向、侦察、攻击；攻击尚未进入统一 Order，需要补齐。
- 复用现有情报、判断、命令、海图及五工作台，补充引导、行动状态和结束反馈。
- LLM 负责交流、候选判断、拟令和表达；GameState 与规则系统裁定事实及后果。
- 事件通过时间或条件触发，敌方采用足以制造压力的有限规则。
- 冻结新战区、美术重做、复杂关系、逐机战斗、完整甲板调度、多日战役和通用存读档。

AP 建议：本场景普通交流和阅读免费，以时间、通信延迟、准备时间和兵力占用承担取舍。
这是待确认的临时规则；本工作稿不改变现有扣减，也不引入新 AP 成本。

## 第一批：开局、时间推进、结束和信息边界

这一批可以先于攻击系统实施；必须先写回归测试。

- [ ] `/advance` 拒绝零和负数，失败请求不改变时钟、AP 或其他状态。
- [ ] 结束时限来自场景配置；保留中途岛现有截止时间语义。
- [ ] 珊瑚海开局加载自身时限，到达时限后结束，再次推进不改变状态。
- [ ] 明确每次推进的步长策略，防止大步长跳过决定性事件或行动阶段。
- [ ] 战中允许查看已获信息与决策记录，禁止返回依赖真值的事实误差评价和隐藏执行状态。
- [ ] 游戏结束后开放有据可查的复盘；只返回该场景相关数据。
- [ ] 场景人物和玩家身份一致，正式入口不混用其他战区角色。

主要代码：`server.py`、`src/state.py`、`src/initial_state.py`、
`src/pipeline.py`、`src/staff/roster.py`、`theaters/*/scenario.json`。

先核对 `GET /log/after-action`、`GET /orders/{id}/audit` 及其前端调用：
运行中记录与战后真值评价分别裁剪，避免简单封锁整个接口而破坏战中功能。
受影响的既有复盘测试需要明确设置游戏阶段。

完成演示：开启珊瑚海 → 正常推进 → 到期结束 → 打开复盘 → 重新开始；
战中无法查询真实敌情误差，非法推进没有副作用。

## 第二批：报告与两次决策

- [ ] 任务简报说明目标、可用兵力、截止时间和基本操作。
- [ ] 初始接触、印证或勘误通过现有情报链产生，不直接注入玩家已知事实。
- [ ] 事件跨 tick 只触发一次，同种子回放一致。
- [ ] 三类参谋根据权限内证据提供判断，玩家可以追问并要求拟令。
- [ ] 侦察和等待改变证据或可用行动时间；新证据到达后仍留出合理反应窗口。
- [ ] 使用真实 LLM 验证角色、响应时间、证据边界和失败重试。

完成演示：玩家经历两次决策，且能说明为什么改变或坚持计划。

## 第三批：最小攻击闭环

- [ ] 攻击接入统一 Order：草稿、签发、传达、执行和回报。
- [ ] 编组经历准备、起飞、搜索、攻击或扑空、返航与结果报告。
- [ ] 与侦察共用飞机资源，校验兵力不足、重复签发和取消边界。
- [ ] 根据真实目标位置、情报时效、距离、投入兵力与防御结算后果。
- [ ] 随机结果可复现；战中仅通过已送达报告获知行动结果。
- [ ] 敌方有有限主动行动，持续等待会改变作战机会或威胁。

完成演示：不同命令和时机能产生可解释的战果或损失，效果不可重复结算。

## 第四批：结局与复盘

- [ ] 为该场景定义明确、可测试的目标、截止时间和失去作战能力条件。
- [ ] 复盘串联证据、参谋判断、玩家决定、命令及后果。
- [ ] 区分当时证据下的判断质量与相对真实情况的事实误差。
- [ ] 一键重开清空场景事件、编组、命令、情报、判断和会话状态。

完成演示：立即攻击、先侦察、持续等待三条路径均可结束；
不要求每条路径必定对应某种胜负。

## 第五批：试玩验收

- [ ] 全量 pytest 通过；前端变更增加适当回归和浏览器验证。
- [ ] 记录真实模型试玩的等待、失败、角色混淆与不可信表达。
- [ ] 邀请 3–5 名未参与开发者试玩，记录阻塞及实际游玩时长。
- [ ] 玩家能独立结束、解释至少一个决定的影响，并可重新开始。

旧会话验证记录：692 项测试通过，命令为
`python -m pytest tests/ -q -p no:capture`。
这是历史基线，不能替代实施后的重新验证。

5–7 个工作日仅作为首轮范围控制目标，不作为完成承诺。
