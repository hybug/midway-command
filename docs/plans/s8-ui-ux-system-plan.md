## 一、目标

保留现有 1942 年海图、木桌、纸张和打字机视觉，但重建信息架构，使玩家能够：

- 在常驻海图上掌握舰队态势。
- 在收报室阅读真正送达的电文。
- 在情报工作台比较证据、判断和标图。
- 在参谋工作台与人物交流并要求正式判断。
- 在 LOG 中追溯命令、判断、批准和结果。
- 在参谋主动来访或冲突升级时得到有优先级的提醒。

设计原则：

> **历史外观保留，现代交互可用。**

---

## 二、当前 UI 的问题

### 信息架构

- NPC 页签同时承担人物选择与全局导航，功能混杂。
- 右栏同时放置聊天、情报板、审批卡和输入栏，空间超载。
- 情报板高度约 168px，无法承载真实文书流程。
- 电报、简报、标图和复盘被统一压成小型卡片。
- 缺少收件箱、待研判、待批准和主动来访的优先级。

### 阅读与操作

- 小字号 `8–10px` 不适合长文判断书和证据链。
- 通用聊天框把“交谈”和“正式命令”混在一起。
- 没有清楚的上下文操作，例如批准、转发、要求判断。
- 地图与文书之间缺少稳定双向导航。

### S4 缺口

- 没有承载参谋主动来访的界面。
- 没有极简人物档案。
- 没有并列展示分歧的位置。
- 玩家转述缺少来源链和接收者记录。

## 三、总体信息架构

一级导航从 NPC 页签改为五个工作台：

```text
CHART    海图、舰队、航线、正式标图和战斗态势
COMMS    收报室、发报、友军通信和通信记录
INTEL    态势摘要、简报、标图、证据
STAFF    参谋名册、对话、判断和极简人物档案
LOG      时间线、命令记录和战后复盘
```

NPC 选择和人物关系下沉到 `STAFF`。

## 四、三层界面结构

```text
L0 常驻态势层
  海图 + 顶栏 + 时间 / AP + 紧急通知 + 当前命令

L1 值班栏
  当前工作台摘要
  未读 / 待处理 / 主动来访 / 待批准
  最近一条参谋判断

L2 旗舰案卷台
  覆盖主界面的工作空间
  承载阅读、比较、讨论、批准和复盘
```

### Commander Desk

- 覆盖海图，但不结束游戏。
- 顶部全局栏保留。
- 不推进游戏时间。
- `ESC` 或“返回海图”关闭。
- 可在内部切换 `COMMS / INTEL / STAFF / LOG`。
- 从海图、通知、参谋和文书进入时保留来源上下文。

### 右栏

右栏只显示摘要与入口：

- 当前工作台。
- 未读数。
- 当前最高优先级事项。
- 最近一条判断或电报。
- 快速切回或打开 Commander Desk。

右栏不再承载完整正文和复杂审批。

- 待批准标图。
- 方位线、距离和可能区域。
- 新旧版本差异。
- 证据来源。
- 参谋长批注。

## M8.4 INTEL 情报工作台

### 四个视图

```text
SITREP    当前态势摘要
BRIEFS    情报判断书
PLOTS     标图提案与正式标图
EVIDENCE  已呈报证据链
```

### SITREP

- 当前已批准接触。
- 最近情报更新时间。
- 搜索覆盖与空白区。
- 未解决冲突。
- 待处理简报。
- 下一次例行简报时间。

### BRIEFS

- 新证据。
- 当前判断与备选解释。
- 置信度、假设和反证。
- 建议和改变判断的条件。
- 参谋长批注。
- 呈报及已读状态。

### PLOTS

- 当前正式标图。
- 待批准、修订、暂缓和驳回项。
- 新旧版本差异。
- 证据和不确定区域。

## M8.7 通知与上下文操作

### 通知等级

```text
INFO
ROUTINE
URGENT
FLASH
STAFF_VISIT
CONFLICT
```

### 行为

- INFO / ROUTINE：更新角标，不打断。
- URGENT：进入待处理列表。
- FLASH：顶部无线电提示并链接 COMMS。
- STAFF_VISIT：显示参谋请求入舱。
- CONFLICT：更新 STAFF，不强制弹窗。
- 已读、已处理、暂缓和忽略分别记录。
- 打开案卷台不推进时间。

### 上下文操作

| 工作台 | 操作 |
|---|---|
| CHART | 推进时间、查看状态、紧急通信 |
| COMMS | 阅读、登记、转发、回复、发报 |
| INTEL | 要求研判、批准、驳回、暂缓、修订 |
| STAFF | 交谈、要求判断、要求解释、转述 |
| LOG | 查看和筛选 |

全局只保留 `ISSUE ORDER` 作为正式命令入口。

### 子模块

- `M8.7.1` NotificationCenter。
- `M8.7.2` 工作台角标。
- `M8.7.3` 待处理队列。
- `M8.7.4` 主动来访。
- `M8.7.5` 上下文操作条。
- `M8.7.6` ISSUE ORDER。
- `M8.7.7` 操作确认和撤销窗口。
- `M8.7.8` 通知恢复与刷新。

### 验收

- 不出现无原因模态弹窗轰炸。
- 所有通知可定位到来源。
- 聊天不能再误触发正式命令。

## M8.8 视觉、可读性与性能

### 视觉原则

- 外层保留木桌、海图、纸张、印章和打字机。
- 案卷正文至少 `13–14px`。
- 紧凑右栏不低于 `11px`。
- 事实、判断、推测使用墨黑、暗红、灰墨。
- 颜色之外必须有文字、线型或印章状态。
- 电报、简报、军令、档案和复盘使用不同纸张结构。
- 减少游戏内 emoji，改用无线电、印章和纸张图标。
- 动画只用于新增事实、主动来访、标图上图和确认动作。

### 可访问性

- 全流程键盘可操作。
- 模态有焦点锁定和 `ESC` 关闭。
- 关键操作按钮有明确动词。
- 滚轮区域不劫持页面滚动。
- 状态不能只靠颜色区分。
- 1440×900 为首要验收尺寸。

### 性能

- 案卷数据按需加载。
- 电报、判断和日志使用虚拟列表或增量渲染。
- 海图动画不得因案卷刷新重复初始化。
- 关闭案卷后释放大列表 DOM。
- 静态守卫测试继续保护缓存号和脚本接线。

## 六、跨系统数据接口

### 来自 S2

- MessageArchive / Inbox。
- EvidenceView。
- IntelBrief。
- PlotProposal / ApprovedPlot。
- WorkItem。
- After Action chain。

### 来自 S3

- JudgmentTask。
- JudgmentResult。
- confidence_band。
- recommendation。
- change_my_mind。
- JudgmentMemory 修订链。

### 来自 S4 v0

- CommanderContactChannel：由史实配置、可直接与 commander 沟通的联系人。
- ChainReport：下级报告沿指挥链上呈。
- CommanderNotice：名单内人员主动提醒。
- DossierSummary：身份、状态、当前关注和最近互动。
- commander 对提醒的处理状态。

延期接口：

- 跨参谋转述或自由通信。
- ReviewNote / 正式复核。
- ConflictDossier、派系和互评。

### 原则

- UI 只消费白名单视图和领域对象。
- UI 不读取 `actual_enemy`。
- UI 不自行合并参谋意见。
- UI 不把未批准 PlotProposal 渲染到默认海图。
- UI 不把聊天文本自动当成正式判断或命令。

## 七、关键用户流程

## 7.1 收到新电报

```text
顶部 FLASH / URGENT 通知
  → 打开 COMMS
  → 阅读原文和时间链
  → 查看是否已路由
  → 跳转相关 BRIEF 或判断
```

## 7.2 审阅标图

```text
INTEL / SITREP
  → PLOTS
  → 查看提案和版本差异
  → 进入审图模式
  → 查看证据与参谋判断
  → 批准 / 驳回 / 暂缓 / 要求修订
  → 返回海图
```

## 7.3 咨询参谋

```text
STAFF
  → 选择人物
  → 提问
  → 系统创建 JudgmentTask
  → 展示判断、建议和依据
  → 可要求解释或修订
```

## 7.4 参谋主动来访

```text
STAFF_VISIT 通知
  → 立即接见或暂缓
  → 进入 STAFF 对话
  → 查看人物当前关注
  → 形成判断或建议
  → 记录 commander 反馈
```

## 7.5 战后复盘

```text
LOG
  → AFTER ACTION
  → 按时间查看证据 / 判断 / 批准 / 命令 / 结果
  → 区分认知错误与事实错误
  → 返回原事件
```

## 十一、总体验收标准

1. 一级导航为 `CHART / COMMS / INTEL / STAFF / LOG`。
2. 右栏只做摘要，完整阅读和审批进入 Commander Desk。
3. 全局聊天框不再承担所有操作。
4. 默认海图只显示正式态势。
5. COMMS 明确区分在途、收到、处理和勘误。
6. INTEL 能完整展示 S2 的证据、简报和标图链。
7. STAFF 档案保持极简。
8. S3 判断与普通聊天有清楚区别。
9. 名单内人员主动提醒不造成弹窗轰炸。
10. LOG 能回溯证据、判断、决定和结果。
11. 案卷文字达到可持续阅读的字号和对比度。
12. 现有 S2 UI 功能不回归。
13. 所有导航和数据权限符合 S2/S3/S4 规格。
14. 1440×900 为主要视觉验收门。

## 十二、暂不纳入本计划

- 移动端完整指挥体验。
- 完整音频系统。
- 3D 舰桥或角色动画。
- 复杂关系网络图。
- NPC 好感度和雷达图。
- 实时多人。
- 自定义界面主题。
- 用户可拖拽的完全自由布局。

## 十三、主要风险

| 风险 | 处理 |
|---|---|
| 案卷台变成另一个信息塞满的页面 | 每个工作台只保留一个主任务和少量上下文 |
| 视觉复刻压过可读性 | 案卷正文统一 13–14px，优先阅读 |
| S4 关系界面过度复杂 | 档案只保留身份、状态、关注、最近互动 |
| 通知太多 | 只有 FLASH 和 STAFF_VISIT 主动打断 |
| 旧 UI 一次迁移破坏功能 | 保留现有模块，按工作台分阶段迁移 |
| 海图和案卷状态不同步 | 单一状态源，案卷操作后统一刷新 |
| 前端误传隐藏真值 | 继续使用白名单接口和泄漏扫描 |
