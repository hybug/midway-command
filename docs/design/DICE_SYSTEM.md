# 骰子系统设计文档

## 核心原则

骰子系统是游戏规则引擎的心脏。任何需要"掷骰判定"的场景都通过统一接口调用。

**设计目标：**
- 统一接口：任何检定都调用同一个 `roll_check()` 函数
- 结果可解释：玩家能看到"为什么成功/失败"
- NPC 参数可影响：不同参谋有不同的修正
- 可扩展：新场景只需定义修正值

## 基础机制

```
基础骰 = d100 (1-100)
修正值 = Σ(各修正来源)
最终值 = 基础骰 + 修正值
```

## 五级结果

| 骰值 | 结果 | 含义 | 游戏效果 |
|------|------|------|---------|
| 95+ | 大成功 | 超出预期，历史转折 | 额外奖励（更多敌舰/更少损失） |
| 70-94 | 成功 | 达成目标 | 正常结果 |
| 40-69 | 部分成功 | 达成但有代价 | 正常结果 + 小惩罚 |
| 10-39 | 失败 | 未达成 | 目标未完成 |
| 9- | 大失败 | 灾难性后果 | 严重惩罚（损失飞机/暴露位置） |

## 修正值来源

### NPC 参数修正（基于 npc_config.py，S2.1 起以代码为准）

| 参数 | 公式 | 说明 |
|------|------|------|
| 能力值 competence | × 2（封顶 +20） | 执行类检定（侦察/攻击/着舰）：执行单位或 NPC 的 competence |
| 自主度 + 主动性 | (autonomy + initiative)（封顶 +20） | NPC 自主决策（roll_npc_decision） |

> 修订记录（2026-09-17，S2.1 骰子缺口审计 #5）：本表旧版 "autonomy × 3 /
> risk_tolerance × 20 / initiative × 15 / competence × 25" 与实现不符，按
> `src/dice.py`（GAME_SPEC §7.3 × 2）修订。侦察检定的 competence 取
> **实际执行单位**（`UNIT_REGISTRY["sbd_scout_section"]`，S2.1 起），
> 不再固定使用 Browning。

## 优势/劣势骰

### 机制

- **优势（Advantage）**：掷 2 个 d100，取较高值
- **劣势（Disadvantage）**：掷 2 个 d100，取较低值
- 不叠加：同时有优势和劣势时，互相抵消

### 优势来源

| 条件 | 效果 |
|------|------|
| 侦察充分（已知敌军大致位置） | 攻击时优势 |
| 日舰正在换弹 | 攻击时优势 |
| 天气晴朗 | 侦察时优势 |
| 玩家准备充分（提前布局） | 多项检定优势 |

### 劣势来源

| 条件 | 效果 |
|------|------|
| 天气恶劣 | 侦察时劣势 |
| 距离过远 | 攻击时劣势 |
| 燃油不足 | 返航时劣势 |
| 信息不足 | 多项检定劣势 |

## 应用场景

### 1. 侦察检定
- **触发**：侦察机进入敌军所在 hex
- **NPC 修正**：执行单位 competence × 2（SBD 侦察中队 = 6 → +12）
- **情境修正**：天气、距离、搜索模式
- **结果**：清晰识别/部分识别/误报/漏报/被击落

### 2. 攻击检定
- **触发**：攻击机进入攻击距离
- **NPC 修正**：执行单位 competence × 2
- **情境修正**：目标状态、距离、弹药类型
- **结果**：命中/近失/未命中/被拦截

### 3. 天气检定
- **触发**：每 6 小时检查一次
- **无 NPC 修正**
- **情境修正**：季节、区域
- **结果**：晴朗/多云/暴风雨/极端天气

### 4. NPC 服从检定
- **触发**：玩家命令与 NPC 性格冲突时
- **NPC 修正**：autonomy × 3
- **情境修正**：紧急程度
- **结果**：完全服从/执行但抱怨/拒绝执行

### 5. 着舰检定
- **触发**：飞机返航着舰
- **NPC 修正**：competence × 2
- **情境修正**：天气、燃油、甲板状态
- **结果**：安全着舰/轻微事故/严重事故/坠毁

## 可复现性与检定记录（S2.1）

- 游戏级种子：`GameState.rng_seed`；检定经 `src/intel/rng.py` 的 `RNGService` 执行。
- 每次检定/抽取追加一条 `CheckRecord`（check_id / check_type / actor_id /
  game_time / random_seed / raw_roll / modifiers / final_roll / degree /
  effects / context）到 `GameState.check_records`。
- 同一局面 + 同一种子 ⇒ 完全一致的检定序列（确定性回放）。
- `roll_check` 支持注入骰源（`raw_roller`）；未注入时回退全局 random
  （仅限旧调用方/测试，游戏管线一律走 RNGService）。
