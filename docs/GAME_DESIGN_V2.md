# 中途岛指挥官 · 核心玩法设计文档 v2

> 基于二战中途岛战役史实的文字角色扮演游戏。
> 核心体验：舰队指挥官通过命令指挥参谋，参谋根据命令提供情报、建议并执行动作。
> 不同参谋或军官的决策带来千变万化的玩法体验。

---

## 一、设计理念

### 1.1 核心愿景

还原二战真实战场。舰队指挥官通过命令来指挥庞大的舰队，舰队的参谋根据命令提供情报、建议，并且执行动作。不同的参谋或者军官不一样的决策带来千变万化的玩法体验。

**关键历史参考**：
- McClusky 多搜 30 分钟，意外发现南云舰队
- "TF34 在哪里？"——全世界都想知道
- Browning 坚决建议提前起飞，押对了日舰换弹窗口

### 1.2 设计原则

1. **LLM 是 NPC 的灵魂** —— 自然语言理解、性格表达、战术判断
2. **规则引擎是游戏的心脏** —— 状态管理、骰子检定、战斗演算
3. **信息不对称是核心** —— 玩家永远不知道完整真相
4. **每个决策都有代价** —— 优势骰带来隐藏风险
5. **史实为基** —— NPC、事件、结局都基于真实历史

## 二、架构边界

### 2.1 LLM 层（NPC 灵魂）

**职责**：
- 自然语言理解（玩家说了什么）
- 性格表达（NPC 怎么说话）
- 战术判断（NPC 怎么理解命令）
- 建议生成（NPC 推荐什么行动）
- 报告转述（用自然语言描述战况）

**不碰**：
- 真实敌舰位置
- 侦察检测结果
- 战斗演算
- 状态修改

### 2.2 规则引擎层（游戏心脏）

**职责**：
- GameState（唯一真相源）
- 骰子系统（检定、五级结果、双刃骰）
- 侦察检测（扇面 + 概率 + 延迟）
- 战斗演算（查表 + 随机）
- 事件调度（时间推进 + 事件触发）
- 信息过滤（每个 NPC 看到不同的信息）

**不碰**：
- 玩家说了什么
- NPC 怎么回复
- 对话历史

### 2.3 边界原则

LLM 决定"NPC 说什么、想做什么"，规则引擎决定"实际发生了什么"。

### 3.2 自主度参数系统

```python
class NPCProfile:
    name: str
    role: str
    autonomy: int  # 0-10，越高越自主
    risk_tolerance: float  # 0-1，越高越冒险
    initiative: float  # 0-1，越高越主动建议
    competence: float  # 0-1，越高执行质量越好
    domain: list[str]  # 职责范围
```

**各 NPC 自主度设定**：

| NPC | 自主度 | 风险容忍 | 主动性 | 能力值 | 职责范围 |
|-----|--------|---------|--------|--------|---------|
| Browning | 8 | 0.8 | 0.9 | 0.9 | 战术决策、舰队部署 |
| Murray | 5 | 0.4 | 0.5 | 0.7 | 本舰航行、CAP、损管 |
| Mitscher | 5 | 0.4 | 0.5 | 0.7 | 本舰航行、CAP、损管 |
| McClusky | 7 | 0.6 | 0.7 | 0.8 | 机群指挥、空中作战 |
| 通信官 | 1 | 0.1 | 0.2 | 0.6 | 电报收发 |
| 情报官 | 3 | 0.3 | 0.6 | 0.7 | 情报分析、敌情判断 |

### 3.3 自主度在游戏中的表现

**低自主度（1-4）**：
- "长官，收到电报。是否转发给 TF17？"
- "根据分析，敌舰可能在西北方向。建议派侦察机确认。"

**中自主度（5-7）**：
- "长官，CAP 已加强至 16 架。"
- "建议左转 300°，缩短距离。您看如何？"

**高自主度（8-10）**：
- "长官，PBY 已起飞搜索西北。"（已经执行了）
- "航向已调整至 280°。"（事后报告）
- "我已命攻击机群待命。"（可能超出命令范围）

## 四、骰子系统

### 4.1 基础机制

```
基础骰 = d100
修正值 = Σ(参数 × 权重)
最终值 = 基础骰 + 修正值

结果分级：
  95+  = 大成功（历史转折点）
  70-94 = 成功
  40-69 = 部分成功（有代价）
  10-39 = 失败
  9 以下 = 大失败（灾难性后果）
```

### 4.2 五级结果

| 等级 | 范围 | 含义 | 例子 |
|------|------|------|------|
| **大成功** | 95+ | 超出预期，历史转折 | McClusky 跟踪驱逐舰找到日舰 |
| **成功** | 70-94 | 达成目标 | 侦察机找到敌舰 |
| **部分成功** | 40-69 | 达成目标但有代价 | 找到敌舰但侦察机被击落 |
| **失败** | 10-39 | 未达成目标 | 侦察机未发现敌舰 |
| **大失败** | 9- | 灾难性后果 | 侦察机被击落，暴露己方位置 |

### 4.3 修正值来源

| 来源 | 公式 | 说明 |
|------|------|------|
| **NPC 自主度** | autonomy × 3 | 越自主，行动越果断 |
| **风险容忍** | risk_tolerance × 20 | 越敢冒险，越可能出大事（好或坏） |
| **主动性** | initiative × 15 | 越主动，越可能抓住机会 |
| **能力值** | competence × 25 | 越专业，执行质量越高 |
| **玩家命令质量** | -20 ~ +20 | 命令越具体，修正越高 |
| **战场条件** | -30 ~ +10 | 天气、敌方状态等 |

### 4.4 双刃骰系统

**核心原则**：每个优势都有代价。

**优势骰（Advantage）**：
- 掷 2 个 d100，取较高值用于当前检定
- 同时掷一个"代价骰"，决定隐藏代价
- 代价骰的结果在后续回合才揭晓

**劣势骰（Disadvantage）**：
- 掷 2 个 d100，取较低值用于当前检定
- 同时获得一个"补偿骰"，用于后续某个检定

**代价类型表**：

| 行动 | 优势骰的好处 | 代价骰的风险 |
|------|-------------|-------------|
| 多派侦察 | 发现概率 +30% | 被敌方发现概率 +20% |
| 集中攻击 | 伤害 +25% | 失败时损失 +40% |
| 提前起飞 | 突袭概率 +35% | 燃油问题概率 +25% |
| 缩短距离 | 攻击精度 +20% | 被攻击概率 +30% |
| 加强 CAP | 防御 +25% | 攻击力量 -15% |

**代价的延迟揭晓**：
- 玩家看到"侦察成功"，但不知道已经暴露
- 玩家看到"突袭成功"，但不知道飞机在返航时坠海
- 玩家在做决策时，只看到优势，不知道代价

## 五、核心循环

### 5.1 循环流程

```
① 玩家下达命令（自然语言）
        ↓
② NPC 理解命令（LLM）
        ↓
③ NPC 决定执行方式（自主度 + 骰子）
        ↓
④ 执行行动（规则引擎）
        ↓
⑤ 等待结果（时间推进）
        ↓
⑥ 结果揭晓（骰子 + 延迟）
        ↓
⑦ 玩家做出下一个决策
        ↓
回到 ①
```

### 5.2 时间机制：动作计数制

**核心规则**：
- 每个回合有 N 个动作点（AP）
- 每次对话消耗 1 AP
- 每次下达命令消耗 1 AP
- AP 用完后，必须推进时间才能继续
- 推进时间后，AP 重置

**AP 配置**：

| 回合类型 | AP 数 | 说明 |
|---------|-------|------|
| 普通回合 | 3 | 日常对话、调整部署 |
| 关键回合 | 5 | 战斗准备、重大决策 |
| 紧急回合 | 2 | 敌袭、紧急情况 |

**动作消耗**：

| 动作 | 消耗 AP | 说明 |
|------|---------|------|
| 和参谋对话 | 1 | 获取情报、建议 |
| 下达命令 | 1 | 调整航向、派侦察机 |
| 等待观察 | 0 | 不消耗 AP，但不推进时间 |
| 推进时间 | 0 | 进入下一回合，AP 重置 |

**设计意义**：
1. 玩家控制节奏 —— 不会被时间追着跑
2. 有意义的选择 —— 有限的 AP 要分配给谁？做什么？
3. 模拟指挥官的注意力 —— 你不能同时和所有人对话
4. 避免信息过载 —— 每回合只能处理有限的信息

## 六、侦察方案系统

### 6.1 设计理念

参谋长不是执行者，而是规划者。他根据玩家的意图生成详细侦察方案，玩家确认后执行。

### 6.2 交互流程

```
玩家: "派侦察机搜索西北方向"
        ↓
参谋长: 查询状态 + 生成方案
        ↓
参谋长: "长官，侦察方案如下：
   飞机: PBY × 6
   搜索扇面: 330° - 30°（西北）
   航程: 250 海里
   高度: 1500 英尺
   预计回报: 1 小时后
   是否执行？"
        ↓
玩家: "执行" / "只派 2 架" / "高度再高一点"
```

### 6.3 参谋长性格偏差点

| 参数 | 默认值 | Browning 偏差 | 说明 |
|------|--------|-------------|------|
| 飞机数量 | 4 架 | 6 架（偏多） | 确保找到 |
| 扇面宽度 | 60° | 40°（偏窄） | 集中力量 |
| 航程 | 200 海里 | 250 海里 | 尽早发现 |
| 高度 | 1000 英尺 | 1500 英尺 | 看得更远 |

### 6.4 玩家调整选项

- "执行" → 按方案执行
- "只派 2 架" → 数量调整
- "高度再高一点" → 高度调整
- "搜索范围再大一点" → 扇面宽度增加

## 七、信息流转

### 6.1 信息层级

```
战场真相（上帝视角）
    ↓ 过滤、延迟、失真
NPC 信息权限
    ↓ 玩家主动询问
玩家信息
```

### 6.2 信息失真机制

| 失真类型 | 来源 | 例子 |
|---------|------|------|
| **数量失真** | 侦察精度 | PBY 报告"两艘航母"，实际有四艘 |
| **位置失真** | 坐标误差 | 报告"方位 320°"，实际是 315° |
| **时间失真** | 信息延迟 | 攻击波 07:00 出发，报告 09:30 才到 |
| **解读失真** | NPC 性格 | Browning 报告"形势有利"，情报官报告"需谨慎" |

### 6.3 信息获取方式

| 方式 | 信息类型 | 延迟 | 精度 |
|------|---------|------|------|
| **侦察机** | 敌方位置 | 30-60 分钟 | 中-高 |
| **电报** | 友军动向 | 15-30 分钟 | 高 |
| **雷达** | 空中目标 | 即时 | 低（只知道方向） |
| **目视** | 近距离 | 即时 | 高 |
| **情报分析** | 敌方意图 | 无 | 低（猜测） |

### 6.4 玩家的信息困境

玩家需要整合多个 NPC 的信息做出决策，每个 NPC 只看到自己权限内的信息，信息可能延迟、不完整、甚至错误。

## 七、事件系统

### 7.1 事件类型

| 类型 | 触发方式 | 例子 |
|------|---------|------|
| **历史事件** | 固定时间 | 中途岛遭袭（06:00） |
| **侦察事件** | 玩家行动触发 | PBY 发现敌舰 |
| **连锁事件** | 前置事件触发 | 攻击成功 → 日军反击 |

### 7.2 事件触发规则

**历史事件**：在固定时间自动触发，不受玩家行为影响。

**侦察事件**：由玩家派侦察机触发，骰子决定是否发现，发现后报告延迟 30-60 分钟。

**连锁事件**：前置事件发生后触发，例：攻击成功 → 日军反击事件（延迟 2 小时）。

### 7.3 事件链示例

```
[04:00] 玩家派侦察机 → 侦察事件触发
[04:30] 中途岛遭袭 → 历史事件触发
[05:00] 侦察报告到达 → 侦察事件结果
[06:00] 玩家决定攻击 → 攻击事件触发
[07:30] 攻击结果报告 → 攻击事件结果
[08:00] 日军反击 → 连锁事件触发
```

## 八、胜利条件与结局

### 8.1 胜利维度

| 维度 | 历史基准 | 超越历史 | 不如历史 |
|------|---------|---------|---------|
| **击沉日舰** | 4 艘 | ≥ 4 艘 | ≤ 2 艘 |
| **美军损失** | 约克城 + 约 150 架飞机 | ≤ 1 艘航母 | ≥ 2 艘航母 |

### 8.2 结局类型

| 结局 | 条件 | 叙事 |
|------|------|------|
| **超越历史** | 沉 ≥ 4 日舰，美损 ≤ 1 | "你做到了 Spruance 都不敢想的事。" |
| **中途岛奇迹** | 沉 3-4 日舰，美损 ≈ 历史 | "历史按你想的方式发生了。" |
| **惨胜** | 沉 ≥ 2 日舰，美损 ≥ 2 | "赢了，但代价惨重。" |
| **惨败** | 沉 ≤ 2 日舰 | "如果这一天没赢，太平洋战争会怎样？" |
| **Browning 独走** | Browning 自主决策导致胜利 | "这场胜利属于 Browning，还是属于你？" |

### 8.3 历史脚注

每个结局附带一段历史脚注，对比真实历史。

## 九、实现优先级

### Phase 1：核心循环（本次实现）

| 优先级 | 内容 | 说明 |
|--------|------|------|
| **P0** | 动作计数制 | AP 系统，每回合有限动作 |
| **P0** | 骰子系统 | 基础骰 + 五级结果 |
| **P0** | 侦察循环 | 派侦察机 → 等待 → 报告 |
| **P1** | 信息延迟 | 报告不是即时到达 |
| **P1** | 信息失真 | 侦察报告有误差 |

### Phase 2：丰富体验

| 优先级 | 内容 | 说明 |
|--------|------|------|
| **P2** | 多 NPC | 舰长、通信官、航空参谋 |
| **P2** | 双刃骰 | 优势骰的隐藏代价 |
| **P2** | 连锁事件 | 攻击 → 反击 |

### Phase 3：完整游戏

| 优先级 | 内容 | 说明 |
|--------|------|------|
| **P3** | 战斗演算 | 攻击结果、损失计算 |
| **P3** | 多结局 | 根据战果触发不同结局 |
| **P3** | 历史脚注 | 每个结局附带历史对比 |
| **P3** | NPC 主动事件 | 最低优先级 |
