# 中途岛指挥官 · 核心玩法策划方案

> 基于二战中途岛战役史实的文字角色扮演游戏。
> 核心乐趣：语言沟通的理解偏差。

---

## 1. 核心玩法循环

```
NPC 报告态势
    ↓
玩家输出自然语言指令（非精确操作）
    ↓
NPC 理解指令 → 根据职责/性格/能力决定"确认与否" → 分解为具体动作 → 执行
    ↓
玩家观察执行结果（状态变化）
    ↓
玩家发现偏差 → 发纠正指令 / 认可
    ↓
（循环）
```

### 关键设计：玩家不直接操作

- ❌ 玩家不说"左转至 220°"
- ❌ 玩家不说"起飞 SBD"
- ✅ 玩家说"准备接敌"、"稳妥点"、"找到就打"
- NPC **理解**后，自行分解为具体操作
- 理解过程受 NPC **性格**和**职位**影响，产生**偏差**

---

## 2. NPC 执行风格：性格决定确认与否

| NPC | 职位 | 性格 | 执行风格 | 示例 |
|-----|------|------|----------|------|
| **Browning（参谋长）** | 战术决策 | 激进、自信、急躁 | **直接执行，事后报告** | 玩家说"准备接敌"→他直接左转、加速，然后说"已按您的命令缩短距离" |
| **通信官** | 信息传递 | 保守、公事公办 | **事事确认** | 玩家说"通知友军"→他问"是否发报通知 TF17？"等确认后才执行 |
| **舰长（旗舰）** | 本舰指挥 | 稳重、有经验 | **小事直接做，大事请示** | CAP 调整直接做；航向改变会问"建议左转 230 而非 220，您看如何？" |
| **航空联队长（CAG）** | 机群指挥 | 专业、飞行员思维 | **技术细节确认** | 玩家说"准备攻击"→他问"俯冲还是鱼雷？多少架？" |

### 执行风格的乐趣来源

**不可预测性**：玩家不知道这个 NPC 会不会先问。
- 对 Browning 必须说得很具体："准备接敌，**但保持 200 海里**"
- 对通信官可以模糊："通知友军我们有行动"
- 对舰长可以信任小事，但大事要盯

**纠正成本**：Browning 擅自执行错了，玩家要花额外对话纠正。
- "Browning，谁让你改航向的？回到 240。"
- Browning 回复："长官，您说准备接敌，我以为... 好，回到 240。"
- 时间流逝，窗口缩小。

## 3. 理解偏差机制

### 3.1 偏差类型

**强度偏差**：同一命令，不同性格产生不同强度理解

| 玩家指令 | Browning（激进） | 舰长（稳重） | 通信官（保守） |
|---------|-----------------|-------------|---------------|
| "准备接敌" | 左转 220°，缩短到 150 海里，机群一级战备 | 左转 230°，缩短到 200 海里，CAP 加强 | 发报友军、保持编队、等待情报 |
| "稳妥点" | 保持 CAP，但缩短到 180 海里（他觉得这已经很稳了） | 维持现状，加强侦察 | 原地等待，不发报 |
| "找到就打" | 立即起飞全部机群 | 先确认目标，再分批起飞 | 请示上级后再行动 |
| "撤退" | 向东撤，保留实力（他不情不愿） | 有序撤离，保持编队 | 通知所有单位，确认安全路线 |

**行动偏差**：对"准备"的理解不同
- 玩家想：先待命，等情报
- Browning 做：机群已挂弹上甲板，随时能起飞
- 结果：机群暴露在甲板上，如果被偷袭损失更大

**优先级偏差**：多任务时的优先级排序
- 玩家说"准备接敌，同时保持侦察"
- Browning：缩短距离 > 侦察（他认为抓人更重要）
- 舰长：保持 CAP > 缩短距离（他认为防御第一）

### 3.2 偏差的表现方式

偏差不是随机数，而是**性格驱动的系统性偏移**：
- Browning 总是比玩家预期更激进（距离更近、动作更快）
- 通信官总是比玩家预期更保守（事事确认、绝不冒险）
- 舰长总是折中，但在防御问题上更谨慎

玩家通过多次交互，逐渐"摸透"每个 NPC 的脾气，学会用不同方式下命令。

## 4. NPC 角色详细设计

### 4.1 Miles Browning · 参谋长（灵魂角色）

**职位**：TF16 参谋长，Spruance 的副手，实际战术决策者

**性格**：
- 激进、果断、 impatient
- 战术嗅觉敏锐，历史上推动了提前起飞
- 对犹豫零容忍，会擅自行动
- 短句、直接、偶尔爆粗口

**执行风格**：**直接执行，事后报告**

**理解偏差特征**：
- 所有命令强度 +1（medium → high，high → maximum）
- "稳妥" = 他认为的稳妥（实际仍偏激进）
- "准备" = "立即行动"
- 忽略限制条件（如"但保持 200 海里"中的"但"可能被忽略）

**玩家交互模式**：
```
玩家: "准备接敌。"
Browning: "明白。左转 220，缩短到 150。机群待命。"
→ 航向已改！

玩家: "Browning，太近了！回到 200 海里。"
Browning: "长官，150 海里才能确保打击窗口... 好，回到 200。但每多一海里，日本人就多一分钟。"
→ 不情愿地改回

玩家: "这次听清楚：准备接敌，保持 200 海里，等我的命令再起飞。"
Browning: "...明白。200 海里。机群待命。"
→ 加了约束条件，他勉强遵守
```

**历史依据**：历史上 Browning 确实擅自推动了提前起飞，Spruance 事后才知道他已经让机群待命。

### 4.2 通信官

**职位**：无线电通信，电报收发

**性格**：
- 公事公办，无个人观点
- 保守，绝不越权
- 每件事都按流程走

**执行风格**：**事事确认**

**理解偏差特征**：
- 不会主动做任何操作
- 所有命令都转化为"是否发报/是否通知"
- 不问战术判断，只问"发给谁、说什么"

**玩家交互模式**：
```
玩家: "通知友军我们有行动。"
通信官: "长官，是否发报通知 TF17（约克城）？电报内容如何措辞？"
→ 等玩家确认

玩家: "发报：TF16 正在接敌。"
通信官: "已发报。TF17 回复收到。"
→ 执行完毕
```

### 4.3 舰长（旗舰 USS Enterprise）

**职位**：企业号舰长，本舰最高指挥

**性格**：
- 稳重，经验丰富
- 对舰和船员安全负责
- 在战术上尊重参谋长，但在本舰操作上有主见

**执行风格**：**小事直接做，大事请示**

**理解偏差特征**：
- CAP 调整、损管准备：直接做
- 航向改变、速度改变：提出建议，等确认
- 如果命令危及本舰安全：会主动提出反对意见

**玩家交互模式**：
```
玩家: "准备接敌。"
舰长: "CAP 已加强至 16 架。至于航向，建议左转 230 而非 220——220 太接近日本水面舰队范围。您看如何？"
→ CAP 直接改了，航向等确认

玩家: "好，230。"
舰长: "航向 230 已设定。"
→ 执行
```

## 5. 时间推进与事件系统

### 5.1 回合制推进

游戏不是实时进行，而是**回合制**：
- 玩家点"推进 15 分钟"按钮
- 时间前进，事件触发
- 事件强制暂停，等待玩家决策

### 5.2 关键事件链（04:00 - 08:00）

| 游戏时间 | 事件 | NPC 反应 | 玩家决策点 |
|---------|------|---------|-----------|
| 04:00 | 开局 | Browning 催促："长官，我们应该提前部署。" | 是否调整部署 |
| 04:30 | **PBY 报告敌航母！** | 通信官读电报；Browning 强烈建议立即行动 | 是否起飞？ |
| 05:00 | 第二条 PBY 报告（更新位置） | Browning 更急："窗口在关闭！" | 是否提前起飞？ |
| 06:00 | 日军攻击中途岛 | 通信官报告中途岛受袭；Browning："他们暴露了！" | 是否立即起飞？ |
| 06:30 | **关键决策窗口** | Browning 擅自让机群待命（如果玩家之前说"准备"） | 是否现在起飞？ |
| 07:00 | 如果起飞 → 机群在途 | 通信官收到各机群报告 | 协调攻击？ |
| 08:00 | 战果到达 | 通信官读战报 | 是否追击？ |

### 5.3 事件驱动的 NPC 行为

NPC 不只是被动等待玩家命令，他们会根据事件**主动行动**：

- **Browning 在 04:30 收到 PBY 报告后**：
  - 如果玩家还没下命令，他会主动说："长官，敌航母在西北 180。我建议立即起飞。"
  - 如果玩家犹豫超过 2 个回合（30 分钟），他可能会**擅自**让机群进入一级战备

- **通信官在收到新电报后**：
  - 自动弹出新消息
  - 玩家必须主动问"有什么新电报？"才能获取详情

## 6. 胜负条件

不是简单的"赢/输"，而是**与历史对比**：

### 6.1 评分维度

| 维度 | 历史基准 | 超越历史 | 不如历史 |
|------|---------|---------|---------|
| **击沉日舰** | 4 艘（赤城、加贺、苍龙、飞龙） | ≥ 4 艘 | ≤ 2 艘 |
| **美军损失** | 约克城 + 约 150 架飞机 | ≤ 1 艘航母 | ≥ 2 艘航母 |
| **决策时机** | 06:30 起飞（历史 Spruance 选择） | 更早抓到日舰换弹窗口 | 错过窗口 |
| **指挥风格** | - | 玩家与参谋的配合比历史更好 | 频繁纠正偏差，效率低下 |

### 6.2 结局类型

| 结局 | 条件 | 描述 |
|------|------|------|
| **超越历史** | 沉 ≥ 4 日舰，美损 ≤ 1 | "你做到了 Spruance 都不敢想的事。" |
| **中途岛奇迹** | 沉 3-4 日舰，美损 ≈ 历史 | "历史按你想的方式发生了。" |
| **惨胜** | 沉 ≥ 2 日舰，美损 ≥ 2 | "赢了，但代价惨重。" |
| **惨重失败** | 沉 ≤ 2 日舰，或美损 ≥ 2 | "如果这一天没赢，太平洋战争会怎样？" |
| **Browning 独走** | Browning 擅自起飞导致大胜 | "Browning 赌对了，但你还是指挥官吗？"（特殊结局） |

### 6.3 特殊结局：Browning 独走

如果 Browning 多次擅自行动，且结果恰好很好：
- 游戏会触发特殊结局
- 旁白质疑："这场胜利属于 Browning，还是属于你？"
- 历史脚注：讨论"领导权与代理权"的边界

## 7. 玩家成长曲线

### 7.1 学习阶段（前 10 分钟）

- 玩家发现 Browning 会直接执行
- 第一次被"擅自行动"震惊
- 学会加约束条件："准备接敌，**但**保持 200 海里"

### 7.2 掌握阶段（10-20 分钟）

- 玩家摸透每个 NPC 的脾气
- 对 Browning 用精确约束
- 对通信官用模糊指令
- 对舰长信任小事

### 7.3 精通阶段（20-30 分钟）

- 玩家利用偏差而非避免偏差
- "Browning，准备接敌！"（知道他会缩短到 150，但玩家其实想要 150）
- "通信官，随便通知一下友军。"（知道他会认真发报，刚好需要正式通知）
- 用不同 NPC 实现"间接命令"

## 8. 技术实现要点

### 8.1 核心循环的技术映射

```
1. NPC 报告态势
   → LLM 生成自然语言（基于当前 GameState + NPC system prompt）
   
2. 玩家发指令
   → Streamlit 文本输入
   
3. NPC 理解 → 执行
   → LLM 解析玩家意图（第一层 LLM 调用）
   → 根据 NPC 性格矩阵调整理解（规则层）
   → 分解为具体动作（规则层 + 第二层 LLM 调用可选）
   → 更新 GameState
   → LLM 生成执行报告（第三层 LLM 调用）
   
4. 玩家观察结果
   → Streamlit 侧边栏状态面板实时更新
   
5. 玩家反应
   → 回到步骤 2
```

### 8.2 理解引擎（规则层）

不用 LLM 做全量理解（太慢），而是：

1. **意图标签化**：LLM 快速分类玩家意图（engage/hold/scout/launch/retreat）
2. **强度评估**：LLM 评估玩家意图的强度（low/medium/high）
3. **性格滤镜**：规则层根据 NPC personality_bias 调整
   - `adjusted_intensity = base_intensity + personality_bias.aggression`
4. **动作生成**：规则层根据调整后的意图生成具体动作
   - `engage + high → set_course(220), speed(30), cap_strength(16)`
   - `engage + medium → set_course(230), speed(25), cap_strength(12)`
5. **自然语言包装**：LLM 将动作包装为 NPC 的自然语言回复

### 8.3 执行确认逻辑

```python
def should_confirm(npc, action_type, action_severity):
    """根据 NPC 性格和动作严重程度决定是否先确认。"""
    
    if npc.name == "Browning":
        return False  # Browning 从不确认
        
    if npc.name == "RadioOfficer":
        return True  # 通信官事事确认
        
    if npc.name == "Captain":
        if action_severity == "minor":  # CAP 调整、损管
            return False
        if action_severity == "major":  # 航向、速度、起飞
            return True
            
    return True  # 默认确认
```

## 9. 不做清单

MVP 阶段坚决不做：

- ❌ 真实地图渲染
- ❌ 音效音乐
- ❌ 多周目存档
- ❌ 玩家扮演日方
- ❌ 实时战斗模拟（战斗用查表 + 随机）
- ❌ 多语言
- ❌ 移动端
- ❌ 战斗动画
- ❌ 3D 模型
- ❌ Mod 系统

---

## 10. 美学方向

- **视觉**：军用文档风，等宽字体，黑白 + 橙色警告
- **文字**：电报体 + 海军行话
- **情绪**：孤独、不确定、长时间等待、瞬间决断
- **节奏**：慢 - 慢 - 慢 - **快！**（大部分时间等待，关键时刻爆发）
- **反例**：不是 RTS，不是 RPG，不是数据模拟器

---

## 11. 核心乐趣验证清单

验证"理解偏差"是否成立：

- [ ] 玩家第一次被 Browning 擅自行动时是否感到惊讶/好笑？
- [ ] 玩家是否会主动学习"如何给 Browning 下命令"？
- [ ] 同一命令给不同 NPC，结果是否显著不同？
- [ ] 玩家是否会利用偏差（故意下模糊命令让 Browning 过度执行）？
- [ ] 纠正偏差的过程是否有趣（而不是烦人）？
- [ ] 时间压力 + 理解偏差是否创造了"赌命决策"的紧张感？

全部 6 项中至少 4 项为"是" → 核心玩法成立。
